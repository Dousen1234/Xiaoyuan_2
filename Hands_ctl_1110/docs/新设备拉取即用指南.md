# 新设备拉取即用指南

> 面向场景：**你换了一台 Linux 机器**（或重装了系统），仓库 clone 下来之后，怎样从零把它跑起来。
> 只讲环境与命令，手爪本身怎么接、协议怎么解，看 [`手爪快速上手指南.md`](手爪快速上手指南.md)。

本指南所有命令都在 `Hands_ctl_1110/` 及其子目录内操作，**不会改动腿臂主工程**。

## 1. 依赖清单

| 依赖 | 用途 | 是否必须 | 检查命令 |
|---|---|---|---|
| `git` | 拉取仓库 | ✅ 必须 | `git --version` |
| `g++` ≥ 8（支持 C++17） | 编译 `testcmd_ssj1110` | ✅ 必须 | `g++ --version` |
| `cmake` ≥ 3.10 | 可选构建方式（`build.sh` 不需要） | ⭕ 可选 | `cmake --version` |
| `can-utils` | `candump` / `cansend` 手工调试 | ⭕ 强烈建议 | `candump -V` |
| `iproute2` | `ip link set can0 up` | ✅ 必须（发行版一般自带） | `ip -V` |
| Python ≥ 3.8 + `python-can`、`pyserial` | 跑 `资料/` 里的厂家 Python 上位机 | ⭕ 可选 | `python3 -c "import can"` |
| `arm-none-eabi-gcc` | 重新编译 STM32 固件 | ⭕ 只在改固件时需要 | `arm-none-eabi-gcc --version` |
| `openocd` / `st-flash` | 刷写固件 | ⭕ 只在刷固件时需要 | `openocd --version` |

### 1.1 安装命令（按发行版选一条）

```bash
# Debian / Ubuntu
sudo apt update
sudo apt install -y git g++ cmake can-utils iproute2 python3-pip
pip3 install --user python-can pyserial

# 只在需要改 / 刷固件时
sudo apt install -y gcc-arm-none-eabi openocd stlink-tools

# Fedora
sudo dnf install -y git gcc-c++ cmake can-utils iproute python3-pip

# Arch
sudo pacman -S git gcc cmake can-utils iproute2 python-pip
```

实测环境（本仓库开发用的机器）：

```
g++ (Ubuntu 15.13.2)       # 支持 C++17
cmake 3.28.3
openocd 0.12.0
st-flash 1.8.0
stm32flash 0.7-1
arm-none-eabi-gcc 15.13.2
gdb-multiarch 15.1
```

**`testcmd_ssj1110` 不依赖任何第三方库**——只用 Linux 原生 SocketCAN（`<linux/can.h>`、
`<linux/can/raw.h>`、`<net/if.h>`、`<sys/socket.h>`）。所以只要 `g++` 有，就能编。

## 2. 拉取仓库

```bash
git clone git@github.com:Dousen1234/Xiaoyuan_2.git
cd Xiaoyuan_2
```

### 2.1 如果 SSH 连不上（`Connection timed out during banner exchange`）

这台机器的 22 端口经常被墙。有两个办法：

**办法 A：走代理（推荐）**

```bash
# 假设本地代理在 7897 端口（Clash / V2Ray 默认）
export https_proxy=http://127.0.0.1:7897
export http_proxy=http://127.0.0.1:7897
git config --global http.proxy http://127.0.0.1:7897

# 验证
git ls-remote --heads origin
```

**办法 B：改用 HTTPS + Personal Access Token**

```bash
git remote set-url origin https://github.com/Dousen1234/Xiaoyuan_2.git
# 之后 git push 时用户名填 GitHub 用户名，密码填 PAT（不是账号密码）
```

> 先确认走哪条路可用，再往下做。`git ls-remote --heads origin` 能打印出
> `refs/heads/hands` 和 `refs/heads/legs` 就说明通了。

### 2.2 分支说明

| 分支 | 内容 |
|---|---|
| `hands` | **只要手爪** —— `Hands_ctl_1110/` 全部内容（241 文件 / 19 MB），不含腿臂代码 |
| `legs` | 腿臂主工程（`examples/`、`include/`、`src/` 等），不含手爪 |

```bash
# 只用手爪（推荐，体积小、目录干净）
git clone -b hands git@github.com:Dousen1234/Xiaoyuan_2.git
cd Xiaoyuan_2/Hands_ctl_1110

# 已有仓库时切换
git checkout hands
```

> ⚠ `hands` 分支**只有** `Hands_ctl_1110/`。如果你还需要腿臂的 `examples/walk_control_V1.cpp`
> 来写联合代码，得另外 `git checkout legs`（两个分支内容互不重叠，需要手动合并）。
> 腿臂合并目前**尚未开始**，详见顶层 `README.md` 的「当前状态」。

### 3.1 编译报错怎么办

| 报错 | 原因 | 解决 |
|---|---|---|
| `'canfd_frame' was not declared` | 内核头文件太老 | `sudo apt install linux-libc-dev` |
| `undefined reference to socket` | 极少见，链接顺序问题 | 用 `./build.sh`（它按正确顺序链接） |
| `-std=c++17` 不支持 | g++ < 7 | 升级 g++，或用 `build.sh` 里改 `CXX=clang++` |
| `warning: ...` 一堆 | 不影响运行 | 本仓库实测 `-Wall -Wextra` 零 warning，出现说明编译器版本差异，可忽略 |

## 4. 起 CAN 通道

这是**唯一需要 root 的一步**，每次开机后做一次。

### 4.1 确认分析仪被识别

```bash
# PEAK PCAN-USB FD 的 VID:PID 是 0c72:0012
lsusb | grep -i 0c72
# 期望：Bus 001 Device 005: ID 0c72:0012 PEAK System PCAN-USB FD

# 驱动模块（峰值）或内核自带
lsmod | grep -i peak

# 是否出现了 can0..can5
ip -br link show type can
```

### 4.2 打开通道

```bash
# 单个通道
sudo ip link set can0 down 2>/dev/null
sudo ip link set can0 up type can bitrate 1000000

# 确认状态
ip -details link show can0
# 期望看到：state UP, bitrate 1000000, <ERROR-ACTIVE>
```

**一次开 6 路**（PCAN-USB FD 会枚举 6 个口）：

```bash
for i in 0 1 2 3 4 5; do
  sudo ip link set can$i down 2>/dev/null
  sudo ip link set can$i up type can bitrate 1000000
done
ip -br link show type can
```

> ⚠ **波特率必须是 1000000（1 Mbit/s）**，且 **CAN FD 必须关闭**。手爪固件是经典 CAN 2.0A。

### 4.3 `sudo` 不可用怎么办

有些机器（或者容器 / snap 环境）会禁用 sudo：

```
sudo: The "no new privileges" flag is set
```

这种情况下 `ip link` 只能由**你自己在终端里手动敲**，本仓库的任何脚本都不会替你提权。
如果确实需要频繁操作，可以让管理员给你配一条 sudoers 免密规则：

```
ssj ALL=(root) NOPASSWD: /usr/sbin/ip link set can* up *, /usr/sbin/ip link set can* down
```

配好之后就能用 `sudo -n` 非交互执行了。

### 4.4 被动监听：确认板子在说话

**这一步不发任何帧，最安全。** 先确认板子在周期性上报：

```bash
candump can0
```

正常应该看到 6 种 ID 的周期帧（基址 11 时）：

```
can0  00B   [8]  01 xx .. .. .. .. .. ..
can0  00C   [8]  .. .. .. .. .. .. .. ..    # 位置帧
can0  00D   [8]  .. .. .. .. .. .. .. ..    # 状态帧
can0  00E   [8]  .. .. .. .. .. .. .. ..    # 诊断帧
```

一条帧都看不到 → 跳到第 6 章排错。

```bash
cd Hands_ctl_1110/testcmd_ssj1110

```

## 6. 排错

### 6.1 一条 CAN 帧都收不到

按顺序查：

```bash
# ① 链路层是不是 UP
ip -details link show can0 | grep -E "state|bitrate"
# 不是 UP → 回到 4.2
# 不是 bitrate 1000000 → 重新 ip link set

# ② 有没有错误计数增长
ip -s -d link show can0 | grep -A3 -i error
# RX errors 持续增长 → 接线/终端电阻/波特率问题

# ③ 硬件接线
#    CAN_H ↔ CAN_H，CAN_L ↔ CAN_L，GND 必须共地
#    总线两端各一个 120 Ω 终端电阻，中间节点不要接

# ④ 板子有没有上电
#    12 V 供电，板载 LED 是否亮
```

### 6.2 `state DOWN` / 起不来

```bash
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 1000000 restart-ms 100
sudo ip link set can0 up
ip -details link show can0
```

若报 `RTNETLINK answers: Device or resource busy`，说明有进程占着这个 socket：

```bash
sudo lsof /dev/can* 2>/dev/null
# 或者干脆换个通道试：can1 / can2
```

### 6.3 能收到帧，但程序报「读不到位置帧」

- 基址不对。默认 `11`，若改过基址要加 `--base <新值>`（范围 11..120）。
- 通道名不对。程序默认 `can0`，用 `--channel can1` 指定。
- 位置帧被别的进程读走了。SocketCAN 默认不广播给多个读者——先 `pgrep -a candump` 杀掉其他进程。

### 6.4 位置读数卡在 ±327.67°

累计行程超过 3431 counts 后 int16 饱和。**这不影响堵转保护，但影响坐标**。
解决办法：重新标零（交互里按 `z`），把当前物理位置定义为 0°。

细节见 [`../testcmd_ssj1110/README.md`](../testcmd_ssj1110/README.md) 的「位置坐标的真相」。

### 6.5 `./build.sh: Permission denied`

```bash
chmod +x build.sh
./build.sh
```

## 8. 环境相关的已知坑

| 坑 | 说明 |
|---|---|
| **全角引号** | 主机上某些终端/输入法会把 `""` 变成 `“”`，C++ 字符串字面量会**静默截断**。写代码时用 `「」` 或半角引号。 |
| **`vcan` 模块不可用** | 这台机器 `modprobe vcan` 失败，所以**不能**用虚拟 CAN 做离线联调，只能靠 `selftest_*` 自测。 |
| **`SO_RCVTIMEO{0,0}`** | Linux 上 `{0,0}` 表示「永不超时」而不是「立刻返回」。要非阻塞必须用 `recv(MSG_DONTWAIT)`。仓库代码已处理。 |
| **SocketCAN 单读者** | 同一通道上多个进程同时读会互相抢帧。调试时先 `pgrep -a candump` 确认没有别的程序。 |
| **MS4931 无电流环** | SENSE 没接 ADC，所以固件**没有任何限流**。`--max-pwm` 建议 ≤ 600。 |
| **无保持力矩** | `CLAW_ACTIVE_BRAKE_ENABLED=0`，断电即松（靠减速箱自锁）。 |
