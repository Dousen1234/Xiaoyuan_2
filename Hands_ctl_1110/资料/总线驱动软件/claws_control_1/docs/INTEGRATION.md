# 与腿臂控制软件的合并约定

## 接口

- 手爪板：STM32F103执行Hall、PWM、位置PID和保护。
- Windows：创芯ControlCANFD.dll；Linux：python-can SocketCAN。
- 载荷协议保持 Classical CAN 2.0A、1Mbps、8字节帧。
- 四只手爪使用四条独立总线；每条总线可复用相同手爪CAN ID。

| 内容 | 手爪接口 |
|---|---|
| 命令 | `0x180` |
| 反馈 | `0x181`位置、`0x182`状态、`0x183`诊断、`0x184`参数、`0x080`故障 |
| 操作 | move、relative、open、grip、seek-open、stop、zero、clear |
| 心跳 | 200ms，沿用当前动作sequence |
| 单位 | 角度0.01°；speed为0.1名义Hall rpm |

## 合并原则

在腿臂程序中封装独立的`ClawModule`，复用现有CAN发送和接收接口。共享一个接收套接字时，必须统一接收后按ID分发，不能让腿臂和手爪模块分别读取同一队列。手爪目标不能复用关节模组载荷定义。

四条总线的通道映射以实际Linux接口为准；KH-UCANFDX6-Mini支持CANFD，但STM32F103手爪板仍使用经典CAN。组号用于选择固件参数，不是CAN节点地址。

## 联调顺序

1. 单独验证每条总线的1Mbps通信、反馈和超时停机。
2. 无运动接入腿臂软件，核对ID、时间戳和丢帧。
3. 统一接收分发和心跳，再进行单路小动作。
4. 最后合并腿臂动作流程和四通道调度。

当前项目未修改腿臂工程，也未完成两套软件的联合实机验证。
