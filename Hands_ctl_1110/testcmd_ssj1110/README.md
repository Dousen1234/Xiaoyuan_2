# testcmd_ssj1110 —— 手爪固件自用控制程序（C++17）

独立的一套控制程序，**不依赖** `claws_control_1/host_demo/` 里的任何代码，自己实现了 CAN 编解码。
**纯 C++17，零第三方依赖**，只用 Linux 自带 SocketCAN。

## 文件

| 文件 | 作用 |
|---|---|
| `claw_can.h` / `claw_can.cpp` | CAN 通信层：协议常量、CRC-8、帧编解码、总线封装（心跳/重试/故障检测） |
| `test_rotate.cpp` | **功能 1**：三指同速持续旋转 → 同速反向旋转 → 往复 N 轮 |
| `test_positionctrl.cpp` | **功能 2**：单路/多路位置控制，键盘输入角度（逆时针为正），500 ms 无霍尔变化断电 |
| `position_ctrl_logic.h` | 功能 2 的纯逻辑：500 ms 看门狗、越界判定（无 I/O，可离线测试） |
| `selftest_sim.cpp` | 离线自测，用模拟固件验证 CAN 流程，不需要硬件 |
| `selftest_position.cpp` | 离线自测，验证功能 2 的看门狗与越界判定，不需要硬件 |
| `build.sh` | 一键编译 |
| `CMakeLists.txt` | 想用 CMake 时用它 |

以后加"功能 2""功能 3"，就在这个文件夹里新建 `test_xxx.cpp`，复用 `claw_can.h` 即可。

## 快速开始

### 1. 编译（无需安装任何库）

```bash
cd Hands_ctl_1110/testcmd_ssj1110
./build.sh                       # 或者用 CMake，见文末
```

要求：`g++` 支持 C++17（GCC 7 以上），Linux 内核带 SocketCAN（标准内核都有）。

### 2. 起 CAN 通道（每次开机后一次）

```bash
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up
ip -details link show can0          # 确认 state UP，且 "fd off"
```

> 一块驱动板 = 一条总线。四个手爪分别接 `can0`/`can1`/`can2`/`can3`，
> **不要**把多块板并到同一条总线（所有板出厂 ID 都是 11，会冲突）。

### 3. 先看计划，不动电机

```bash
./test_rotate --dry-run     # 连这条命令发出什么帧都打印出来
./test_rotate               # 只打印计划，不发帧
./selftest_sim              # 离线自测，纯软件，不碰硬件
```

### 4. 真机运行

```bash
./test_rotate --confirm
```

## ⚠ 必读：两种模式的区别

固件的 `RUN_IN`（opcode 0x0E）是**唯一能真正持续旋转**的命令，但它的占空比在固件里
写死为 `CLAW_RUN_IN_DUTY_PERMILLE = 1000`（满速），**没有速度参数**。

而带速度参数的位置命令受 `0..120°` 行程限制，只能"转过去再转回来"。

所以有两种模式，用 `kMode` 选择：

### `kMode = kModeRunIn`（默认，推荐）

| 项目 | 说明 |
|---|---|
| 命令 | `RUN_IN`，三指同方向满占空比 |
| 速度 | **由固件固定**，`kRotateSpeedRpm` 不生效 |
| 时长 | ✅ `kRotateSeconds` 精确生效 |
| 行程 | 无限制（一直转） |
| 风险 | 满占空比开环输出，若顶到机械限位，800 ms 内无霍尔变化 → 固件判堵转并锁故障 |

想改物理转速，只能改固件里的 `App/Inc/claw_config.h`：

```c
#define CLAW_RUN_IN_DUTY_PERMILLE  1000U    /* 改这个，比如 500 就是半速 */
```

改完必须用 Keil 重新编译烧写。**这是固件改动，不是上位机改动。**

### `kMode = kModePosition`

| 项目 | 说明 |
|---|---|
| 命令 | `SET_TARGET` + `FLAG_RELATIVE` |
| 速度 | ✅ `kRotateSpeedRpm` 生效，合法范围 **4.0 – 17.0 rpm** |
| 时长 | ⚠ 实际时长 ≈ 摆幅 ÷ 速度，`kRotateSeconds` 只用来算摆幅 |
| 行程 | 摆幅 = `速度 × 6 × 时间` 度，**超过 120° 会被固件截断** |

程序会自动打印提示：

```
单向摆幅        : 120.0°  (速度×时间算出 240.0°)
⚠ 摆幅超过固件 120° 行程上限，已被截断；
  实际每段约 2.50s，而不是 5.00s
```

## 安全设计

| 机制 | 实现 |
|---|---|
| 默认不动电机 | 不加 `--confirm` 只打印计划 |
| 累计时长上限 | `kMaxTotalSeconds`，超出拒绝启动 |
| 心跳 | 每 200 ms 一次（固件看门狗 500 ms） |
| 换向静默 | 每次停机后静默 350 ms（固件要求 ≥300 ms） |
| 异常自动停机 | `ClawBus` 析构时必定发 `STOP`（即使抛异常） |
| 故障立即中止 | 收到故障帧立刻抛异常并停机，退出码 `2` |
| Ctrl+C | 捕获后发 `STOP`，退出码 `130` |

退出码：`0` 正常 / `1` 参数错误 / `2` 通信或固件故障 / `3` 结束时仍有故障 / `130` 用户中断。

## 功能 2：单路 / 多路位置控制（test_positionctrl）

对**一块板上的一个或多个电机**做相对位置控制。运行中用键盘输入角度，选中的电机相对**当前位置**转动该角度。

默认控制哪几路由源文件顶部的 `kMotors` 决定，也可以在运行中用 `m1` / `m12` / `m123` 随时切换。

### 用法

```bash
./test_positionctrl --help
./test_positionctrl --dry-run                      # 只看要发什么帧
./test_positionctrl                                # 打印计划，不进交互
./test_positionctrl --confirm                      # 真机交互运行（默认组合）
./test_positionctrl --confirm --motors 12 --max-pwm 600
./test_positionctrl --confirm --motors 123 --max-pwm 600 --set-zero
```

### 参数

| 参数 | 说明 |
|---|---|
| `--motors COMB` | ★ 启动时控制的电机组合：`1` / `2` / `3` / `12` / `13` / `23` / `123`，也接受 `1,2`、`1+2`、`m12`、`M1 M3` |
| `--motor 1\|2\|3` | 已弃用，等价于 `--motors N`（old 用法仍可用） |
| `--sign +1\|-1` | **逆时针符号**。`+10°` 实际转反了就改成 `-1` |
| `--speed RPM` | 名义轨迹速度，固件合法 4.0..17.0 |
| `--max-pwm N` | 用 `PARAM_SET` 把选中通道的 `maximum`(id=6) 和 `startup`(id=7) 改成 N‰，**只改 RAM** |
| `--set-zero` | 启动时发一次 `SET_ZERO`，把**当前位置**定义为 0°（**不会转动电机**） |
| `--zeroed` | 固件已执行过 `SET_ZERO`，目标下限从 −30° 改为 0°（**不发帧**，只改本程序的判定） |
| `--confirm` | 确认驱动电机（不加只打印计划） |
| `--dry-run` | 不打开总线 |

> `--set-zero` 与 `--zeroed` 不是同一件事：前者**真的发 `SET_ZERO` 帧**（所以下限自动变成 0°），
> 后者只是告诉本程序「固件已经标过了」，既不发帧也不清计数。

### 交互命令

| 输入 | 作用 |
|---|---|
| `10` / `+10` / `-25.5` | 相对当前位置转动该角度，逆时针为正 |
| `m1` `m2` `m3` | 切换为**单路**控制（会先校验新通道霍尔合法性） |
| `m12` `m13` `m23` | ★ 切换为**两路**控制（固件无单帧，会拆成两条顺序执行） |
| `m123` | ★ 切换为**三路同时**控制（一条 CAN 帧） |
| `m1,3` / `m1+3` | 组合的其它写法，与 `m13` 等价 |
| `z` `Z` `zero` `SET_ZERO` `set_zero` `标零` | ★ **标零** `SET_ZERO`，把当前位置定义为 0°（不动电机，需二次确认） |
| `q` | 退出（退出前发 `STOP`） |
| `?` | 帮助 |

### ★★★ 多路控制的三个固件约束

多路同时控制会遇到三个**固件层面**的约束，程序全部替你处理了，但你必须知道它们存在。

#### 约束 1：电机掩码编码在 opcode 里，只支持 4 种组合

固件没有独立的「掩码字段」，选中哪几路是**由 opcode 决定的**（`claw_control.c:139`）：

```c
case CLAW_COMMAND_SET_TARGET:    return 0x07;  // 三路
case CLAW_COMMAND_SET_TARGET_M1: return 0x01;
case CLAW_COMMAND_SET_TARGET_M2: return 0x02;
case CLAW_COMMAND_SET_TARGET_M3: return 0x04;
```

| 你想要的组合 | 固件能否一条帧搞定 | 本程序的做法 |
|---|---|---|
| M1+M2+M3 (`0x07`) | ✅ `SET_TARGET` | 一条帧，真·同时 |
| 单个 M1/M2/M3 | ✅ `SET_TARGET_Mx` | 一条帧 |
| **M1+M2 (`0x03`)** | ❌ 无对应 opcode | 拆成 M1 → M2 **顺序执行** |
| **M2+M3 (`0x06`)** | ❌ | 拆成 M2 → M3 顺序执行 |
| **M1+M3 (`0x05`)** | ❌ | 拆成 M1 → M3 顺序执行 |

而且**两条单路命令也无法真正重叠**：`start_move()` 里
`if (claw_state == CLAW_STATE_MOVING) return CLAW_RESULT_BUSY;`
第一路还在 MOVING 时第二路必然被拒，所以只能等前一路到位再发下一条。

> ⚠ 因此 **`m12` / `m13` / `m23` 不是同时动**：M1 先转完，M2 才开始转。
> 如果中途第一路堵转，**第二路根本不会再动**，位置会不同步。程序会在结果里明确提示。

#### 约束 2：多路目标坐标是「选中各路位置的平均值 + 增量」

```c
// claw_control.c:772-781
for (motor = 0; motor < CLAW_MOTOR_COUNT; ++motor) {
  if ((motor_mask & (1U << motor)) != 0U) position_sum += motors[motor].position_counts;
}
target_mdeg += ClawControl_CountsToAngleMilliDeg(position_sum / (int32_t)selected_count);
```

**所以「输入 +10°」不等于「每路都转 +10°」**，除非三路起点完全相同。

实例：M1=10°、M2=20°、M3=30°，输入 `+10°`

- 参考坐标 = `(10+20+30)/3 = 20°`
- 目标坐标 = `20 + 10 = 30°`
- 各路实际转角 = 目标 − 各自起点：

| 电机 | 起点 | 目标 | 实际转过 |
|---|---|---|---|
| M1 | 10° | 30° | **+20°** |
| M2 | 20° | 30° | **+10°** |
| M3 | 30° | 30° | **0°（完全不动）** |

程序每次输入前都会算一遍这个表：若三路起点相差 > 1°，就打印每路
`→ 实际转过 ±X°` 并提示：

> 若希望每路都转过同样角度，请改为**逐路单独控制**（`m1` / `m2` / `m3`）。

三路起点一致时（正常同步状态）没有这个问题，输入多少就各转多少。

#### 约束 3（最危险）：某一路先到位时固件会单独给它断电

```c
// claw_control.c:1154  ClawControl_Task()
if (motor_done[motor]) {
  set_pwm(motor, 0U);              // ← 只断这一路
  motors[motor].command_direction = 0;
  ClawPid_Reset(...);
  continue;
}
```

该路霍尔随即停止变化。**如果看门狗只看霍尔，500 ms 后就会误判堵转，然后发 `STOP`
把另外两路仍在正常运转的电机一起掐死。**

所以本程序的多路看门狗（`MultiHallWatchdog`）用**诊断帧的每路占空比**作为判据：

```
某路 duty > 0        →  被驱动过，正常监视霍尔
某路 duty 从 >0 变 0  →  固件已单独停它 → 标记「已完成」，退出监视，不算堵转
某路 duty > 0 但霍尔 500 ms 不变  →  真堵转 → 立刻 STOP
```

合法霍尔码与位置死区的规则和单路完全一致（非法码跳变、同码重复都不算进展）。

> ★ `feed_duty()` 必须在 `feed_hall()` **之前**调用（同一帧内先判电源再判霍尔），
> 否则「到位那一帧」会被误认为是堵转。`selftest_position` 里
> `test_multi_watchdog_one_motor_done()` 专门锁死了这个用例。

#### 多路的超时预算按「最大位移」算

固件按最长的那条路径算 `trajectory_ms`，所以本程序也用 `max |各路位移|`
（而不是输入增量）计算超时预算，起点差得越多预算越长。

### ★ 安全保证：500 ms 无有效霍尔变化就断电

```
从"该电机最后一次有效霍尔码变化"起计时
  >= 500 ms  →  立刻发 STOP 断电，重新提示下一个角度
```

"有效变化"的定义与固件一致：诊断帧里该电机霍尔码改变，**且新码在固件合法扇区表
`{0x1,0x5,0x4,0x6,0x2,0x3}` 内**。非法码跳变（如 `0x07 → 0x00`）不计入进展。

**这条判定在上位机侧做，比固件自身的 `CLAW_STALL_TIMEOUT_MS`(800 ms) 堵转保护更早**，
所以撞限位时固件不会锁存 fault，你可以连续输入下一个角度而无需 `CLEAR_FAULT`。

### ★★ 位置坐标的真相：累计行程，会被 int16 钳死

**位置帧里的角度不是绝对位置**，而是固件从「上电 / 上次 `SET_ZERO`」以来**累计走过的
霍尔边沿数**换算出来的角度：

```c
// claw_control.c:919  ClawEdgeIRQ()
motors[motor].position_counts += logical_step;   // 无界累加，没有任何限幅

// claw_control.c:324  ClawControl_Init()      -> position_counts = 0（上电清零）
// claw_control.c:851  CLAW_COMMAND_SET_ZERO   -> position_counts = 0（唯一的运行时清零点）
```

而发位置帧时被**硬钳在 `int16`**：

```c
// claw_control.c:1244  ClawControl_BuildPositionFrame()
int16_t angle_cdeg = clamp_i16(ClawControl_CountsToAngleMilliDeg(...) / 10L);
```

`1 count ≈ 0.09547°`，所以累计行程一旦超过 **≈3431 counts（327.67°）**，位置帧就永久贴在
`±327.67°`，**真实位置再也读不到**。

#### 为什么必须重视：饱和时上位机与固件的坐标不一致

| | 计算相对目标时用什么 |
|---|---|
| 固件 | `motors[m].position_counts`（int32，**未饱和的真实值**） |
| 上位机 | 位置帧里的 `±327.67°`（**已饱和**） |

举例：真实位置 500°（显示成 327.67°，饱和）。你输入 `-210.00°`：

- 上位机算：`327.67 − 210 = 117.67°` → 在 `0..120` 内 → **放行**
- 固件算：`−210 + 500 = 290°` → 静默截断到 `120°` → 实际走 `120 − 500 = **−380°**`

**你以为转 210°，电机实际转 380°，几乎是两倍。** 中途撞死限位才靠 800 ms 堵转保护断电。

所以本程序**不会**在饱和状态下给你算「可行增量范围」：

- 启动时读到 `|角度| >= 320°` → **拒绝进入交互**并提示必须标零；
- 交互中若读数饱和 → 每次输入角度都判为 `Saturated` 并提示先按 `z`；
- 判定逻辑在 `position_ctrl_logic.h` 的 `check_target()` / `position_saturated()`，
  由 `selftest_position` 离线覆盖。

#### 标零怎么用

```
z                     # 交互中直接标零（需敲 SET_ZERO 确认）
--set-zero            # 启动流程里自动标一次（饱和时自动启用，无需再确认）
```

`execute_set_zero()` 会：停稳 → `SET_ZERO` → 重读位置帧验证真的回到 0° 附近。

**四条必须知道的语义**（`claw_control.c:843` 逐字确认）：

1. **不会让电机转动** —— 只清计数，不使能 PWM。
2. **一次清三路** —— 固件的循环是 `for (motor = 0; motor < CLAW_MOTOR_COUNT; ++motor)`，
   **不支持只标一个电机**。
3. **把「当前物理位置」定义为 0°** —— 标零之后 `0°` 就是当时停的那个位置，
   `0..120°` 也从那里算起。所以最好在**已知机械参考点**上标零。
4. **只写 RAM** —— `position_counts` 与 `zero_calibrated` 掉电全丢。每次上电
   `position_counts` 从 0 重新累加，会再次涨到饱和，**每个上电周期都要重新标零**。

#### 推荐的完整上电流程

```bash
./test_positionctrl --confirm --motors 2 --max-pwm 600 --set-zero
```

如果希望 `0°` 有明确物理意义（例如「完全张开」），先手动让电机退到张开限位，再标零：

```bash
# 方法 A：用本程序 —— 先转到一个你能确认的参考姿态，再按 z
./test_positionctrl --confirm --motors 2 --max-pwm 600
> z

# 方法 B：用固件自带的 seek-open（开环顶到张开限位，单路 500ms 无有效霍尔变化即停）
#   注意：这会真的驱动电机，且不会自动设零
```

### 两个固件限制（程序已替你处理）

**1. 相对位移会被静默截断**

`claw_control.c:ClawControl_HandleCommand()` 把「当前位置 + 增量」换算成绝对坐标后按
下列范围**静默截断**：

| 状态 | 允许坐标 |
|---|---|
| 未执行 `SET_ZERO` | `−30° .. +120°` |
| 已执行 `SET_ZERO` | `0° .. +120°` |

从 0° 连续输入 `+50°` 三次，第三次不会到 +150°，而是被截在 +120°。
本程序在发命令**前**就算出目标坐标并检查，越界直接拒绝并提示可行增量范围。

**2. 太小角度不会动作**

固件 `CLAW_POSITION_DEADBAND_COUNTS = 1`，而 1 Hall count ≈ 0.0955°。若
`|路径| <= 1 count`，`start_move()` 直接把该电机标成 `motor_done`，**根本不会进
MOVING**，上位机只能空等到超时。程序对 `|Δ| < 0.5°` 直接拒绝。

### ⚠ 本板 PID 上限只有 100‰

`claw_profiles.h` 里 group 1 的三路 profile 都是：

```c
{12, 0, 0, 150, 100, 100, 100, 2, 400}
//                 ↑min ↑max ↑startup  ← minimum == maximum
```

`ClawPid_Step()` 里输出被夹在 `[minimum, min(ceiling, maximum)]`，两者相等
⇒ **只要有误差，输出恒为 100‰**，PID 退化成定速开环。100‰ 只有跑合时
（`CLAW_RUN_IN_DUTY_PERMILLE 1000`）的 1/10，**带机械负载很可能转不动**，然后
500 ms 被看门狗断电。

需要力矩时加 `--max-pwm 600`（或 900）。这改的是 RAM 里的 `runtime_profiles`，
**掉电恢复板卡默认值**，不写 Flash、不需要重新烧写。

## 踩坑记录

### `SO_RCVTIMEO{0,0}` 不是「立刻返回」，是「永不超时」

**现象（2026-11-16 实机）**：标零成功、交互提示正常，输入 `30` 后：

```
[M2] 当前 M2  +0.00°   输入 角度(度,逆时针为正) / m1|m12|m123 / z / q > 30
      → 目标坐标 +30.00°（相对 +30.00°）
      ▮                        ← 光标停在这里，再也不动
```

连 `→ 发送相对位移 ...` 那一行都没打出来，电机当然一动不动。

**根因**：`execute_move()` 开头要先冲掉接收缓冲区里的陈旧帧（否则上轮残留的
`HOLD + target_reached` 会被误判成「立刻到位」），写的是：

```cpp
while (bus.poll(0).has_value()) { }      // 缓冲区一空就该退出
```

而 `SocketCan::recv()` 当时这样实现「非阻塞」：

```cpp
timeval tv{};                 // = {0, 0}
setsockopt(fd_, SOL_SOCKET, SO_RCVTIMEO, &tv, sizeof(tv));
read(fd_, &frame, sizeof(frame));
```

**Linux 上 `{0,0}` 表示「永久阻塞」，不是「零超时」**。要零超时只能用
`recv(..., MSG_DONTWAIT)`。缓冲区一旦读空，`read()` 就挂在那里等下一个帧——
固件在 IDLE 下只发周期反馈帧，而循环每读到一帧又继续读，理论上只在两次
反馈帧之间有空窗……实际表现就是**永久卡死**。

已用一个独立探针验证（拒绝全部入站帧的过滤器 + 2 秒 `alarm`）：

```
>>> read() 在 2 秒内没有返回 => SO_RCVTIMEO{0,0} 表示「永不超时=阻塞」
```

**修复**（`claw_can.cpp`）：

```cpp
ssize_t n;
if (timeout_ms <= 0) {
  n = ::recv(fd_, &frame, sizeof(frame), MSG_DONTWAIT);   // 内核保证立刻 EAGAIN
} else {
  timeval tv{};
  tv.tv_sec  = timeout_ms / 1000;
  tv.tv_usec = (timeout_ms % 1000) * 1000;
  ::setsockopt(fd_, SOL_SOCKET, SO_RCVTIMEO, &tv, sizeof(tv));
  n = ::read(fd_, &frame, sizeof(frame));
}
```

同时把冲缓冲循环改成**有界**，这样即使将来 `poll` 语义再出问题也不会死锁：

```cpp
for (int guard = 0; guard < 64; ++guard)
  if (!bus.poll(0).has_value()) break;
```

回归测试在 `selftest_sim` 第 10 组（`EmptyTransport` 假传输层，4 项断言）。

> 教训：`poll(0)` / `read(timeout=0)` 这类「非阻塞」写法在不同 API 上层出不穷地写错，
> 而一旦写错就是**静默永久阻塞**——不报错、不超时、没有任何提示。
> 凡是「排空缓冲区」的循环，都应当同时具备**非阻塞语义**和**次数上界**两道保险。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `打不开 CAN 通道: can0` | 通道没 up 或没装驱动 | 按上面第 2 步起通道；`ip link show` 确认 UP |
| `1.5s 内没收到 seq=... 的状态帧` | 基地址不对 / 波特率不对 / 板子没上电 | 确认 `kBaseId`；确认 `bitrate 1000000`；用 `candump can0` 看有没有反馈帧 |
| `固件拒绝，result=BUSY` | 还在动，或换向静默不足 | 程序已自动等 350 ms；若手动连发，加长间隔 |
| `固件报故障 通信超时` | 心跳没喂上 | 检查 bus 是否正常；程序已内置 200 ms 心跳 |
| `固件报故障 电机N(堵转)` | 手指顶到限位 / 线接反 / 霍尔坏 | 减小时长或改用 position 模式；检查接线 |
| `固件报故障 同步超差` | 三指负载差异太大 | 减小 `kMotorMask` 单独测；或降低速度 |
| 模式 `position` 下 `result=RANGE` | 速度不在 4.0–17.0 | 改 `kRotateSpeedRpm` |
| 当前角度恒为 `+327.67°` / 正角度全被拒 | 位置帧 int16 饱和（累计行程超过 ≈327°） | 加 `--set-zero` 或用 `z` 标零，见上面「位置坐标的真相」 |
| 标零后仍显示 `+327.67°` | `SET_ZERO` 没被固件接受（BUSY / 通道在动） | 确认电机已完全停住再标零；看是否返回 `result=BUSY` |
| **输入角度后打印了「目标坐标」就再也不动、连「发送相对位移」都没有** | `poll(0)` 阻塞在 `read()` 上（`SO_RCVTIMEO{0,0}` 在 Linux 上是「永不超时」不是「立刻返回」） | 已修正为 `recv(MSG_DONTWAIT)`；旧版请重新编译，见下方「踩坑」 |

### selftest_position —— 功能 2 的安全逻辑

针对 `position_ctrl_logic.h` 的纯逻辑测试，**不需要 CAN 通道、不会动电机**：

| 组 | 验证内容 |
|---|---|
| 霍尔码合法性 | 合法表 `{1,5,4,6,2,3}`；`0x0`/`0x7` 判非法（悬空的典型读数） |

| 看门狗：非法码 | `0x1→0x7→0x0` 的抖动**不能**拖延断电 |
| 看门狗：码不变 | 同一个码重复上报 2 秒也算堵转 |
| 看门狗：与固件对比 | 断言 500 ms < 固件 800 ms（撞限位时固件不锁 fault） |
| 目标越界（未标零） | `-30°..+120°`；从 0° 走 -40° 被拒并提示最小增量 |
| 目标越界（已标零） | `0°..+120°`；从 0° 走 -10° 被拒 |
| 连续 +50° 累计 | 第 3 次（到 150°）被拒，并提示“最多还能走 +20°” |

| 位置帧饱和判定 | `±327.67°`、`±327.0°` 判饱和；`0°`/`120°`/`−30°`/`319.9°` 正常；320.0° 为边界 |
| ★ 饱和拦截目标 | 饱和时 `check_target()` 首判 `Saturated`，**不** 先报 `AboveMax`，避免给出错误可行范围 |
| `AngleState` | 角度与饱和标记绑在一起；`update(0)` 能清掉饱和（模拟标零后） |
| 超时预算 | 10°@8rpm ≈ 10.21 s；120°@4rpm 夹到 14 s（早于固件 15 s） |
| **电机组合解析** | `"1"→0x01`、`"12"→0x03`、`"123"→0x07`、`"m1,3"→0x05`、`"M1 M3"→0x05`、`"0"/"14"/""→0` |
| **掩码拆分** | `0x07→{0x07}`、`0x03→{0x01,0x02}`、`0x06→{0x02,0x04}`、`0x05→{0x01,0x04}`；拆分后每份都被固件支持 |
| **多路坐标语义** | 起点一致时各路位移相同；★ 起点 10/20/30 输入 +10° ⇒ 各路转 +20/+10/**0**°；参考坐标只算选中路 |
| **位置死区** | `≤1 count` 的路径固件直接判到位，`will_move_of()` 必须给出 false |
| **多路超时预算** | 按**最大位移**而非输入增量算 |
| **多路看门狗** | 三路正常不误报；全停转 500 ms 判堵转；★ **M2 断电停转而 M1/M3 照转 ⇒ 不判堵转**；断电后恢复占空比会撤销完成标记；未选中/本不动的路不参与判定；非法码与同码重复都不算进展 |
