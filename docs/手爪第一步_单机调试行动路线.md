## 2. 安全基线（不满足就不上电）

1. **12 V 独立电源**给驱动板，带可调限流（初次建议限流 **1.0 A**）。
2. **急停 / 快速断电开关**串在 12 V 上，手边可及。
3. 手指动作范围内**不放手指、线缆、易损件**。
4. **所有接线在全部断电状态下完成**（PC、适配器、驱动板、12 V 全部断开）。
5. 电源正负极**按板上丝印**接，不按线缆颜色。
6. 上电顺序：**先 12 V，后插 USB**；断电顺序相反。
7. 异常第一动作：**切 12 V**，不是先按 Ctrl+C 或敲 `stop`。

## 3. 断电线序（一只手爪 / 一块板 / 一条总线）

### 3.1 系统链路

```text
PC --USB--> KH-UCANFDX6-Mini(can0) --CANH/CANL/GND--> 驱动板 --M1/HALL1,M2/HALL2,M3/HALL3--> 三指手爪
                                        ↑
                                    12V 独立电源（共地！）
```

### 3.2 CAN 侧（3 根线）

| 适配器 | 驱动板 |
|---|---|
| CANH | CANH |
| CANL | CANL |
| GND | GND |

- **GND 必须接**。CAN 收发器需要共地参考；只接 CANH/CANL 会出现随机错误帧、bus-off。
- 手爪用独立 12 V 供电没问题，但**12 V 负极、驱动板 GND、适配器 GND 三者必须连通**。

### 3.3 电机 / Hall 侧（按模组编号一一对应）

驱动板上丝印的是 `M1/M2/M3`（= **本地电机号 1/2/3**）和 `HALL1/HALL2/HALL3`。手爪模组上贴的是**模组号**（4/5/6/…）。**这两个号不相等，必须按组号做偏移：**

> **本地电机号 = 模组号 − (组号 − 1) × 3**

本机架上是**组 2 = 模组 4–6**，所以：

```text
模块 4 → M1 (UVW) + HALL1 (GH1.25 5Pin)
模块 5 → M2 (UVW) + HALL2 (GH1.25 5Pin)
模块 6 → M3 (UVW) + HALL3 (GH1.25 5Pin)
```

- 一只三指手爪上，若某一侧只有一指，那一指对应的是**本组的最后一个模组**（组 2 就是模组 6）。
- 每组 **UVW 三相线与 Hall 5Pin 必须成对**，不允许 M1 的 UVW 配 HALL2。
- 线束标识不清时：**先贴标签、拍照、记录线序，再通电**。
- **接错模组的后果**：三指按错误的对应关系动作，`0x181` 里的三个角度与实际手指对不上，后面所有方向判断、零点判断全部失效。这里花 10 分钟核对，能省掉后面一整天。

### 3.4 终端电阻（最容易翻车的一步）

| 位置 | 说明 |
|---|---|
| KH 适配器通道 | 每通道板载 120 Ω（确认是否有拨码/跳线可关） |
| 驱动板 | **U11 必须用导线短接**（出厂已短接）→ 板上自带 120 Ω |

**验收值（断电、万用表电阻档，量 CANH–CANL）：**

| 读数 | 判定 |
|---|---|
| ≈ **60 Ω** | ✅ 两端各一个 120 Ω，正确 |
| ≈ **120 Ω** | ⚠️ 只有一端，长线/高速下可能不稳，需补一个 |
| ≈ **40 Ω** | ❌ 三个终端，必须去掉一个 |
| 0 Ω / OL | ❌ 短路或断路，停止 |

波特率 **1 Mbit/s**，**CAN-FD 必须关闭**，DLC 固定 8。

## 5. 上电自检（不发任何帧）

1. 合上 12 V → 观察板上 LED。
2. LED = **PC13**，低电平点亮：
   - 正常：**每 500 ms 翻转一次**（慢闪）。
   - 有故障：**每 100 ms 翻转一次**（快闪）。
   - 不亮 / 常亮 / 无规律：MCU 没跑起来或 IWDG 复位循环，**立即断电**。
3. 用手轻推手指：应有阻尼感（NBRAKE 上电为高 = 不刹车，但 MOS 关断状态下仍能感到磁阻）。
4. 手摸驱动板温度，常温。
5. **关键预期：本板上电大概率直接"快闪"。**
   原因是 `HAL_CAN_ErrorCallback` 在 bus-off / error-passive / RX FIFO 溢出时会把 `CLAW_FAULT_COMM_TIMEOUT`（`0x80`）**锁存**，适配器上电瞬间的电气毛刺就足以触发。
   **2026-10-21 的 15 份日志里，每一次上电都是 `state=3 / fault=128`。**
   所以看到快闪**不要当成接错线**，这是已知现象，后面一条 `clear` 就能解（§9.1）。
6. 插 USB，`ip -br link show type can` 确认 **`can0`** 出现。

## 9. 分级动作阶梯（一级一级过关，不跳级）

### 9.1 清故障（仅当 0x182 显示 FAULT 时）

```bash
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 clear
```

> 规则：**正常停止用 `stop`，只有 FAULT 状态才用 `clear`**。`clear` 不启动任何动作。
>
> 实测依据（`192341_778`、`192651_153`、`190422_128` 三份日志）：发 `clear` 前 `0x182` 是 `state=3 fault=128`，`clear` 后 20 ms 内变成 `state=0 fault=0`，**100% 成功**。
> `0x080` 故障帧可能会在 `clear` 前后重复一两次（日志里有这个现象），**不算异常**。

### 9.2 单指点动 —— 确认方向与 Hall 计数

`jog` 是固件层限幅的短脉冲：**200 ‰ 占空比 / 200 ms / ≤10 counts**（组 2 的模组 6 特殊为 30 counts），就是专门为这一步设计的，不会飞车。

```bash
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 jog 1 --dir 0
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 jog 1 --dir 1
```

逐指做 1→2→3。每次观察：

- **`--dir 0` 与 `--dir 1` 是否让手指朝相反方向动**。
- Hall 计数是否跟着变（`0x183` 里有 Hall 码与计数）。
- 是否出现 `No Hall progress` 提示 → 该指电机线或 Hall 线有问题，或已顶到机械端。

> ❌ **`jog` 在这块板上从来没有被执行过**（15 份日志里一条都没有）。所以本节是**真正的新内容**，不要假设它一定正常，第一次就按“单指、目视、手边放着 12 V 开关”的方式做。

**只有在确认方向反了的情况下**，才去改 `App/Inc/claw_config.h`：

| 现象 | 改哪里 |
|---|---|
| DIR 电平与实际方向相反 | `claw_direction_high[3] = {0U, 0U, 0U}` 改对应位为 1 |
| Hall 计数符号与实际方向相反 | `CLAW_M1/M2/M3_HALL_COUNT_SIGN` 改 -1 |

改完必须 **Rebuild + 烧录**。若方向和计数都正常，**不要动这几个宏**。

### 9.3 单指寻张开端

```bash
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 seek-open 1
```

- 固件会以本通道 `seek_pwm`（组 2 为 **900 / 1000 / 900**）朝张开方向推，直到 **500 ms 无 Hall 变化** 判定到位（"堵转 ≠ 机械零点"，只是到达端点）。
- 超时 5 s（此时会锁存 `CLAW_FAULT_SYNC`，因为**超时不等于到达端点**）。
- 打印 `No Hall progress: output stopped. Inspect the physical endpoint; zero was NOT set.` 是**正常结果**，不是错误。
- 逐指 1→2→3 都做一遍。

> ✅ **实测已跑通过**（`192656_218`）：三指同时 seek-open，`0x183` 的 Hall 码 `[5,3,5] → [5,1,3]` 确实变了，占空比在 ≈1.1 s 后逐路降到 0，全程 `fault=0`。
> 但那个日志是**三指一起**跑的，**单指 seek-open 还没跑过**。

### 9.4 确认张开端 → 设逻辑零点

**这是唯一需要人工判断的一步。**

1. 断电，用手把三指**一起**推到完全张开位置，肉眼确认三指都顶在机械限位上、没有卡在半路。
2. 上电（12 V 先、USB 后）。
3. 确认 `0x182` 中 `state = IDLE`、`fault_mask = 0`。
4. 执行：

```bash
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 zero
```

`zero` 把当前三路 Hall 计数**全部清 0** 并置 `zero_calibrated = true`，不产生任何动作。

> `MOVING` 或 `grip_active` 时发 `zero` 会被回 `BUSY` 拒掉；`fault_mask != 0` 时 `zero` 不会把状态置回 IDLE（仍留在 FAULT），**必须先 `clear`**。
>
> ❌ **`zero` 在这块板上从来没有被执行过。** 所以现在 `CLAW_PREZERO` 保护仍在生效（相对命令下限 -30°）。
>
> 之后 `open` 就是"回这个张开位"。**零点只存在于 RAM，掉电丢失**，每次重启都要重新确认或重新 `zero`。

### 9.5 小角度位置动作（位置 PID）

未 zero 前，相对命令下限被限制在 **-30°**（commissioning 保护）；zero 后下限回到 0°，上限 120°。所以**必须先完成 9.4 再做位置动作**。

```bash
# 三指同时到绝对角度 10°
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 move 10

# 相对当前位置再走 5°
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 relative 5

# 单指到绝对角度 8°
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 f1 8

# 回张开位（逻辑 0，不自动找机械限位）
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 open
```

> ❌ **位置 PID（`move` / `relative` / `f1..f3` / `open`）在这块板上从来没有被执行过。**
> 已跑过的只有 `clear`、`seek-open`、`grip`。位置环是**完全未验证**的部分，也是第一步最需要盯的环节：
> 冷启动时 `kp=12` 对 628.5:1 的减速箱偏软，可能出现“走到一半就不动”或“反方向小振荡”，都属于调参前的已知风险，**先小角度（≤10°）、逐指试**。

要点：

- 角度单位是**减速箱输出侧角度**（度），由 Hall 输入侧计数换算（总减速比 628.5:1）。**不是指尖位置传感值。**
- `--speed` 默认 4.0 rpm（Hall 轨迹速率，不是实测转速），可选范围 **4.0–17.0**。
- **到达目标后 PWM = 0**，位置模式下**没有保持力矩**，手指会被外力推动。这是设计行为，不是故障。

### 9.6 夹持（`grip` + `HOLD`）

```bash
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 grip --clear
```

- `grip` **不接收角度、不用位置 PID**，三指各自用 `grip_pwm` 独立闭合。
- 每一路连续 **500 ms 无 Hall 变化** → 该指转入自己的 `hold_pwm`，整机进入 `HOLD`。
- **`HOLD` 期间上位机必须每 200 ms 发心跳**；`claw_demo` 会自动发。**心跳断 > 500 ms 立即关闭输出**。
- 想长时间保持夹持，必须让 `host_demo` 进程一直运行；进程退出 = 松开。

> ⚠️ `HOLD ≠ 已经抓牢`。本板 **SENSE 未接 MCU ADC**，没有电流环、没有夹持力闭环。`HOLD` 只代表"输出停在 hold_pwm"，不代表夹住了物体。

结束夹持：

```bash
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 stop
```

> ✅ **实测已跑通 5 次**（`192724` / `192746` / `192931` / `192948` / `194021`），夹持结论：
>
> - `MOVING` → `HOLD` 的耗时稳定在 **2.55–2.99 s**，与 `grip_stall_ms = 500` 逐指先后进入 hold 的过程一致。
> - 三路 PWM 稳定在 **948 / 948 / 948**（日志里 `0x183` 存的是 `duty/4`，所以真实值是 948‰ ≈ `hold_pwm` 950 的舍入）。
>   → 三指确实都进到了 `HOLD`，没有哪一路卡在 `grip_pwm` 或 `max_pwm`。
> - 全程 `fault=0`，包括 `ki=20` 的模组 5，**没有 SYNC 故障、没有超时**。
> - `HOLD` 期间能看到手指被外力推动的痕迹（Hall 码每 500 ms 跳一次，角度有 0.1–0.2° 级别的缓慢漂移），这正是“开环 PWM 保持”的正常表现。
> - 所有日志的 `target_reached` 都是 `False` —— `grip` 本来就不是位置动作，**这不是失败**。

```bash
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 params set 1 seek_pwm 900

python3 -m host_demo.claw_demo --channel can0 --claw-group 2 params set 2 grip_pwm 965
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 params set 3 grip_pwm 900
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 params set 1 hold_pwm 950
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 params set 2 hold_pwm 950
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 params set 3 hold_pwm 950

# 回读并保存
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 params save claw2_params.json --force

# 板子重启后恢复
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 params load claw2_params.json
python3 -m host_demo.claw_demo --channel can0 --claw-group 2 params show
```

文件对应关系：手爪 1/2/3/4 → `claw1_params.json` … `claw4_params.json`，四份分开维护。**当前这只手爪用 `claw2_params.json`**。

> `params set` 在 `MOVING` 或 `grip_active` 时会被回 `BUSY` 拒掉；`value < 0` 回 `RANGE`。
> 实测零值 `params show` 已在 §8.1，所以 `set` 只需要改那些“要动”的项，价值观状就不用重发。

**什么要烧录、什么不用：**

| 改动 | 是否需重新烧录 |
|---|---|
| 上位机脚本、JSON 参数 | ❌ 不需要 |
| 板卡上电默认参数 | ✅ 需要 |
| 组号 `CLAW_PROFILE_GROUP` | ✅ 需要 |
| 控制逻辑、保护逻辑、引脚 | ✅ 需要 |

**先不要动**（保持出厂值，避免引入未验证变量）：

- `CLAW_COMMISSIONED_MASK = 7`
- `claw_module_profiles[12]` 里的 PID 与 `max_pwm/startup_pwm/startup_ms`
- `CLAW_SYNC_FAULT_COUNTS / TIME_MS`
- `CLAW_ACTIVE_BRAKE_ENABLED = 0`

这几项全部标注为 **UNCALIBRATED（未校准）**，且组 2 的 `ki=20` 只在模组 5 上试过、未做硬件验证。调 PID 是第二步之后的事。

## 11. 必须接受的能力边界（写进交接记录）

| 边界 | 说明 |
|---|---|
| PWM ≠ 电流 ≠ 力矩 | PWM 只是导通占空比（‰） |
| Hall ≠ 指尖位置 | Hall 只反映**减速箱输入侧**相对计数，不能代表手指末端实际位置 |
| 无电流 / 无力闭环 | SENSE 未接 MCU ADC |
| 位置到位即 PWM=0 | 位置模式**无保持力矩** |
| `HOLD` ≠ 抓牢 | 只是输出停在 hold_pwm |
| 全部参数未校准 | 12 行 profile 全是初始值，包含模组 1–3 |
| 心跳检测范围有限 | 500 ms 看门狗**仅在 MOVING 或 grip_active 时生效**；IDLE 掉线不会报警 |
| 总线错误锁存 | 出现 bus-off / error-passive / RX FIFO 溢出 → 置 `CLAW_FAULT_COMM_TIMEOUT` 并**锁存**，必须 `clear` 才能恢复 |
| 无节点地址 | 6 个 CAN ID 全是编译期 `#define`，板上**没有**运行时改 ID 的机制 |
| 板上只认 `0x180` | 硬件验收滤波器只放行标准数据帧 `0x180`，其它 ID 直接被硬件丢弃 |

## 12. 应急操作（不依赖 Python）

进程卡住 / Python 崩了 / 来不及等的时候，用 `cansend` 直接发（已用固件同款 CRC-8/SAE-J1850 算好）：

```bash
# 正常停止
cansend can0 180#01010200000000C5

# 清故障（仅 FAULT）
cansend can0 180#01010300000000AF

# 心跳（维持 HOLD，需每 200 ms 一条）
cansend can0 180#01010500000000CE

# 单指点动 M1，dir=0
cansend can0 180#0101090000000111
```

> 帧格式：`[0]=ver=1 [1]=seq [2]=opcode [3]=flags [4:5]=target_cdeg(i16le) [6]=speed_drpm [7]=CRC8(bytes 0..6)`

**但第一优先永远是切 12 V，不是发帧。**

|---|---:|---|---|---:|---|

所有手爪都走 **`can0`**，换手爪时**只换物理线 + 改 `--claw-group`**，通道名不变。

**四只手爪的 CAN ID 完全相同，靠"不同总线"区分。第一步一次只接一块板，绝不要把两块板并到同一条总线。**

## 附：引脚事实（改固件时才需要）

| 功能 | 引脚 |
|---|---|
| PWM M1/M2/M3 | TIM1 CH1/CH2/CH3 = PA8 / PA9 / PA10（20 kHz，polarity LOW） |
| DIR M1/M2/M3 | PA0 / PA1 / PA2 |
| NBRAKE M1/M2/M3 | PA3 / PA4 / PA5（active-low，上电置高 = 不刹车） |
| Hall M1 | PB6 / PB7 / PB8 |
| Hall M2 | PB9 / PB10 / PB11 |
| Hall M3 | PB12 / PB13 / PB14 |
| LED | PC13（低电平亮） |

- 9 个 Hall 脚全部配置为 `GPIO_NOPULL` + 双边沿 EXTI。若手爪内部 Hall 板上没有上拉，需外部加 **4.7–10 kΩ 到 3.3 V**。
- **PA9/PA10 被 PWM 占用，不能用 USART1 调试串口。**
- `PB13`（Hall）与 `PC13`（LED）不冲突，不要看错。
